# Visual and audio evaluation

Run `python vision_data/build_review_set.py` to create a review queue and recording-level split manifest. It preserves the existing reels test assignment. All seven user-recorded takes are grouped as one player in training. The held-out test includes three reel players. There is currently no validation player, so use additional independent players for model selection and keep the test players untouched until the final comparison.

`review.csv` includes every retained user frame and a frame approximately every three seconds from each reel. Paths are relative to `datasets/<dataset>/`. `prompted_swara` describes a take-level prompt and `estimated_swara` is an audio-derived candidate based on an inferred tonic. Neither is independent ground truth. Check the actual synchronized source and manually fill `verified_swara` and `usable`. Label each visible hole 1–6 from the blowing end as open, closed, half-covered, or unknown. Unknown represents an obscured or ambiguous state. Record known Sa and check tuning separately before evaluating audio. Do not copy estimated swaras into verified labels without review.

Train six hole classifiers only on reviewed training frames and their mirrored copies. A test set needs verified note labels and/or visible hole states. Compare per-hole metrics and coverage on reviewed test frames, and use the same independently verified note intervals to compare audio-only and audio-plus-vision accuracy and latency. Select models and fusion rules on separate validation players, then run the final comparison once on held-out test players. The current data has no manually reviewed frame-level hole or swara labels, so no unbiased accuracy or improvement can yet be reported.
