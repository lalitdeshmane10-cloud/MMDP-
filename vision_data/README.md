# Vision dataset preparation

Run `python vision_data/prepare.py` from the project root. It requires Python and `opencv-python`. The output defaults to `datasets/vision_prepared` and contains one full-resolution JPEG per second and an annotation CSV. Choose a different sample spacing with `--interval`, or use `--output` for a new directory. The script refuses to overwrite an existing nonempty output directory so reviewed annotations are preserved.

Each row points to its source recording and original label and includes the frame's timestamp in milliseconds. `prompted_swara` is the take-level prompt, not a verified frame label. `verified_swara`, `usable`, `review_notes`, and all six hole columns start empty. Label each hole from the blowing end as `open`, `closed`, `half-covered`, or `unknown`. Mark frames unusable when the flute is not being played or the image is unsuitable. Confirm the sounding swara using the original synchronized recording before filling `verified_swara`. The audio-derived pitch can support review, but it is not ground truth.

The `split` field is intentionally empty. Assign entire recordings and, when additional players are available, entire players to a split. These seven recordings contain only one take for each prompted swara, so they cannot independently support a per-swara held-out recording evaluation yet. Consecutive frames from one recording should never be treated as independent train and evaluation examples. Keep alternate fingerings as separate labeled examples, and retain all six hole states even when evaluating subsets of holes.

`python vision_data/mirror_frames.py` creates horizontally mirrored copies under `mirrored_horizontal` and a manifest linking each copy to its original frame. The original `annotations.csv` remains the source of labels. Join through `source_frame_path` so later annotations apply to both copies. Keep each copy with its original recording and apply augmentation only to the training split. Hole numbering starts from the blowing end and remains unchanged by mirroring. Mirrored images are synthetic and should be evaluated against recordings from different players.
